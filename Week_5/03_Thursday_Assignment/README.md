I compared three differnt structure types, CSV, JSON, and object.  I use a simple example containing basic employee information to see how the data could be represented in each format. 

If the program only needed to store high-level demographic data, I think the CSV format is the easiest to read and work with.  CSV files are organized in rows and columns, which makes them easy to open in Excel.  This would allow someone to quickly sort, filter and analyze the employee information without needing additional programming.

If the employee data became more complex, such as including multiple phone numbers, departments, account numbers or addresses, I think JSON would be the better choice.  JSON handles nested data much more effectively than CSV and allows related information to be grouped together in a more structured way.

I personally don't prefer the object style because it requires more code to create and access the same information that can be stored in CSV or JSON.  However, for a large database, this style can become more valuable.  The different classes can represent different types of information and work together, making the application easier to organize.
